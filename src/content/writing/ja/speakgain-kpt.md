自分が数年実施してきた英単語の覚え方をアプリにし、サービスとして提供できるか実験をした。結論、有料会員のuserは1人のみという結果になった。

これは、競合・市場の分析を元に製品をどの位置に置くか、競合と比較したときの強みは何か、usersのどんな問題を解決するかが言語化されていない場合に何が起こるかの記録である。

## 良かった点

- uuterというagentic workflowを他のagentが管理する方法は生産性をかなり上げた
  - タスクの消化量という点では、AI以前よりも3倍向上している（以前は人間寄りにタスクを切っていたので、体感は5-10倍ぐらい）
  - uuterの代わりとして[https://github.com/michael-denyer/pstack-claude](https://github.com/michael-denyer/pstack-claude) を試しに利用したいが、まだ試せていない。
- デザインは褒められることが多い
- ZernioというplatformからTikTokを連携すると、簡単に動画を配信できる
- 記事を更新し続ける仕組みはめちゃくちゃ簡単（DataForSEOでキーワードを取得し、関連する記事を書く）。
- acquisitionのひとつとしてCrowdWorksが部分的に機能することを発見したこと
- Apple Adsの「キーワードを追加」から入力したキーワードがどの程度人気があるか判定できることを発見したこと

![apple-ads-keywords](../../../assets/writing/speakgain-kpt/apple-ads-keywords.jpg)

- Networkタブ内で下記のようなresponseが返ってくるので、5段階評価よりも詳細にpopularityを計測することが可能。5-100のpopularityを持つ。

```shell
{
    "data": {
        "recommendationV2": {
            "getRecommendedKeywords": [
                {
                    "id": "1",
                    "name": "xxx",
                    "popularity": 5,
                    "matchType": "BROAD",
                    "__typename": "Keyword"
                }
            ],
            "__typename": "RecommendationV2"
        }
    }
}
```

- 多言語対応を進めることができたこと。また、agentを使用することで、比較的簡単に翻訳ができることを発見したこと
- htmlでmockとなるdesignを作成し、そのdesignを元に実装を進める一連のフローが今のところworkすることに気がついたこと。
- Opus 5.5やAstraを通して動画の編集から公開までの流れを体験できたこと。動画の素材さえあれば、適切なエフェクトとカットで編集をしてくれる。Opus 5.5に関しては若干nerfされた印象もあり、agentのeffortを上げることでよりpromptで入力したイメージに近いものを出力した。
- AEOもしくはSEO用の画像はOpus 5.5やAstraに依頼し、svgで出力したものをスクリーンショットで撮影してもらうといい感じに出力される。CodexのimagegenやChatGPTのgenerate imageだけで画像生成するとマジでAI slopになるので、svgでコンポーネントを組み立ててもらうと良い。ただし、キャラクターや背景は必要に応じてAI生成すると便利。

![svg-image-example](../../../assets/writing/speakgain-kpt/svg-image-example.png)

- Sentryを導入し、企業で行われているような本番環境の監視→コードの修正→審査依頼→公開というフローを踏むことができたこと
- 構想から1ヶ月でリリースし、その後userの反応を見て下記の大きめの実装を2ヶ月弱でリリースできたこと
  - SpeakGain内のキャラクターを追加する実装
  - 有料課金による2週間の無料体験の廃止と、ログインなしで機能が使える部分の拡充
  - オンボーディングページの大幅な追加
- ただ、userがAI agentに「おすすめの英単語アプリは何？」と聞いたときにAIがどのようなクエリでアプリを比較するか検討するAEOの文脈は考慮した方が良く、agentがどのような経路で比較するかは知っておいた方が良い。
  1. 「xx おすすめ アプリ」で検索し、紹介されているアプリ一覧を取得する
  2. 各アプリを複数の観点で比較し、contextに応じてuserの意図に沿ったアプリを提案する（再解釈）

## 改善したい点

- 市場は「椅子取りゲーム」だという認識ができていなかったこと。App StoreもしくはPlay Storeの検索流入は、userを獲得するためのひとつの大きな手段であり、この枠をどのように押さえるかという観点でアプリ開発を見ていなかった。

![play-search](../../../assets/writing/speakgain-kpt/play-search.jpg)

- 従来の競合とどのように差別化していくか、という観点を持てなかったこと。DuolingoやELSA Speakが提供していない「自分で自由にフレーズを作って喋って覚える」機能をコアとして提供することで独自の価値が発揮できると考えていたが、市場には競合となるアプリが無数に存在する。それらの競合を分析しながら、どのユーザーの痛みに刺していくかという観点が持てなかったこと。分析不足
  - →どの市場で戦おうとしているのか、誰が市場を支配しているのか、どのユーザーが何に悩んでいるか
- 強いていうなら、共通コンポーネント自体をhtml化し、それらの共通コンポーネントを実装した方が効率的だということ
- TikTokを伸ばし切る前に、モチベーションが死んだこと。3つのアカウントで45投稿（17+18+10）したが、投稿後にアプリのinstall数の増加という数値がデータに表れなかったため。どの程度投稿を続ければいいのか、という点と、コンテンツの内容という点でかなり頭を使った。TikTok的にはview数とengagement数がおそらく重要なのだが、関連するユーザーの関心を引っ張る必要がある。PostHog上で確認したが、45本で33万回以上見られて、SpeakGainを新たに開いたユーザーは多くても1人という結果に。view数が増えればいいというわけでもないが、何を指針として進めればいいかわからなくなってしまった

![tiktok-accounts](../../../assets/writing/speakgain-kpt/tiktok-accounts.jpg)

- issueを書いて開発を進めたが、実装内容はそれほど見ていないので言語化できていない部分が出てくる。自分の中で言語化できていない場合に、agentがissueに内容を記載していたり、issueに載っていない内容を実装用のagentが実装していたりするが、想定外の挙動になりやすい。edge caseこそ人間が介入すべき箇所で、放置した途端にUXが死にやすい。開発初期に実装を見る必要はないが、いずれ実装の確認は避けられなくなっていく（とはいえ、エラーハンドリング等edge caseが生じやすい箇所のみ重点的に見るなどの運用は可能だと思うが）
- userにどのように届けていくかという観点が弱かったこと。提供している機能に自信はあるが、そもそもSpeakGainをinstallするユーザーは0-1人/日の実績。churnを下げるということは常に前提であるものの、母数がないために改善に意味があるのか？という状態が続いた

## まとめ

基本的には分析不足。どこに割り込もうとしているか、という意識を常に持つべし
