エージェント開発 · セキュリティ

エージェントが何をしているか、見えるように。

どのエージェント開発がチームに合うかは、動かしてみるまで分かりません。動き始めたら、実行ごとに、何を変えたか、何を読んで実行したか、マージされたか差し戻されたかを見えるようにします。合うものは残し、合わないものはやめられます。

エージェント開発ワークフロー

Issue → 計画 → 実装 → レビュー → PR。作業はエージェントが、判断は人が持つ。

  • →実行の記録：各エージェントが何を変え、何がマージされ、何が差し戻されたか
  • →Claude Code / Codex によるマルチエージェント開発
  • →モデルをまたいで共有する skill と指示
  • →マージ前のレビューと CI のゲート

セキュリティ

書き込み権限とシェルを持つエージェントは、新しい攻撃面です。そのように扱います。

  • →各エージェントが何を読み、書き、実行したかのログ
  • →エージェントの権限とサンドボックスの設計
  • →Issue・ドキュメント・Web 経由のプロンプトインジェクション
  • →シークレットをエージェントの文脈に入れない設計

エージェントを使っているチーム

企業にも個人開発者にも。エージェントがリポジトリで動き始めたら、実行ごとに、何を変えたか、どこに触れたか、マージされたか差し戻されたかを見えるようにします。そこから、本当に合うワークフローが分かります。

エージェントのセキュリティレビュー

エージェントが何を読み、書き、実行できるのか。それを洗い出し、危険な経路を見つけ、具体的な対策をお渡しします。

どれが合うか分からなくても大丈夫です。今取り組んでいることを教えてください。
